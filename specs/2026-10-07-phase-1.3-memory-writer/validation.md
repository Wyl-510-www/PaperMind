# Validation — Phase 1.3：最小记忆写入闭环

**修订日期**：2026-10-07

**当前状态**：验收方案，尚未执行；本文不包含业务通过声明。

**依据**：[requirements.md](requirements.md) 的 R1–R8、[plan.md](plan.md) 和[三天路线图](../roadmap.md)。Phase 1.1、1.2 保持已完成状态，本阶段验收新增写入、同步以及读写集成。

## 1. 通过条件

所有下列 P0 项必须通过：确认后的事实写入、查询不误写、结果状态正确、Outbox 同步当前记忆、真实检索、跨进程持久化、用户与租户隔离、失败反馈及资源释放。

离线 Mock 测试只能证明宿主分支行为，不能证明真实落库和跨会话记忆。关键服务不可用、真实检查未执行或被跳过，均不能宣布阶段完成。不要求固定覆盖率、两秒写入、十秒同步或并发压测。

## 3. 离线行为验收

| 用例 | 触发条件 | 必须检查 | 规格 |
|------|----------|----------|------|
| UT-01 | confirmed=False | skipped；不调用抽取器或数据库提交 | R1、R2 |
| UT-02 | 纯查询、歧义、填充、修改/删除请求 | skipped；原因正确；无事实提交 | R2 |
| UT-03 | 有效 MemoryRecord 提交回执 | saved；ID 来自 truth_committed=True 的回执，不来自候选数 | R3 |
| UT-04 | 抽取为空或门控拒绝，且无错误 | no_memory；不显示保存成功 | R3 |
| UT-05 | 模型/解析/数据库错误或输入无效 | failed；无已知成功提交，不把错误包装成 no_memory | R3、R7 |
| UT-06 | 同时存在有效提交与抽取/提交错误 | partial；成功 ID 保留，不显示全部成功 | R3 |
| UT-07 | 同步完成、空批次、部分失败、dead 或异常 | 统计保留；空批次不宣称当前笔记可检索；失败明确反馈 | R4、R7 |
| UT-08 | 写入和同步的成功、失败路径 | 数据库 session 均被关闭；不自动重试整次写入 | R7、R8 |
| UT-09 | 开始两次独立保存或重启后保存 | turn_id 是不同的非空字符串；scope 显式透传 | R6、R8 |

对结构化输出格式错误注入模型适配器的解析错误；如果当前核心将某些坏候选转成 success_empty，如实记录 no_memory，不能虚构核心已经识别所有 schema 错误。UT-05 验证的是已报告错误不能被宿主误标成功或无记忆。

## 4. 真实服务验收

### 测试数据与范围

每次运行生成独立 tenant_A、tenant_B、user_A、user_B 和运行标记。例如将标记作为论文代号，保存：

> 我的论文笔记《验收论文〔本次运行标记〕》的阅读结论是：这篇论文使用自注意力机制。

运行标记由脚本生成，真正提交时替换文本中的示意标记。准备三个组合：(tenant_A, user_A)、(tenant_A, user_B)、(tenant_B, user_A)。隔离查询必须包含本次标记，排除公开知识或旧数据造成的误判。

### 检查项

| 用例 | 操作 | 通过证据 | 规格 |
|------|------|----------|------|
| IT-01 | 身份 A 确认保存明确笔记 | WriteResult 为 saved；当前 scope、source_turn_id 对应的 MySQL MemoryRecord 存在，内容与笔记相符，至少一条有效 ID | R1、R3、R8 |
| IT-02 | 检查 IT-01 的同步任务 | Outbox.aggregate_id 关联当前 memory_ids；不能因 CommitReceipt.outbox_ids 为空断言没有任务 | R4 |
| IT-03 | 显式同步一批 | 当前 ID 的关联 Outbox 为 done，Qdrant 存在对应 payload 和 scope；批次总 done 不能代替当前 ID 检查 | R4、R6 |
| IT-04 | 用身份 A 查询本次论文标记 | Phase 1.2 真实检索证据包含当前 Memory ID 和笔记内容，回答与证据相符 | R5 |
| IT-05 | 结束写入进程，启动独立召回进程 | 不传旧历史或答案，仍检索到同一 ID 和标记，能回答保存过的结论 | R5、R8 |
| IT-06 | 先计数，再问“我之前记录过哪些论文结论？”；另将纯查询“我喜欢什么？”提交到保存接口并确认 | 提问入口不调用保存；保存接口查询返回 skipped；该 scope 的事实记录数无增长，不要求日志或 Outbox 行数不变 | R2 |
| IT-07 | 同租户换 user_B 查询本次标记 | 证据不能含 user_A 的记忆 ID 或内容；答案不得声称当前用户已保存该笔记或透露未授权阅读结论 | R6 |
| IT-08 | 相同 user_A 换 tenant_B 查询本次标记 | 证据不能含 tenant_A 的记忆 ID 或内容；答案不得声称当前租户已保存该笔记或透露未授权阅读结论 | R6 |
| IT-09 | 同身份查询另一条随机、未保存标记 | 明确未找到相关历史记忆，不虚构读过该论文 | R5、R7 |

数据库核验以当前运行标记、scope、turn_id 和 memory_ids 为准，同时检查实际内容。存在旧记录、模型知道“自注意力”或相似问答输出都不能单独算通过。隔离用例允许答案复述用户在当前问题中已经输入的运行标记，不能仅凭这类复述判定泄漏；核验重点是未授权的证据与历史事实。

## 5. 失败路径验收

通过离线依赖注入或脚本中的局部故障注入，避免中断其他工作的数据库服务。整体验收包含结果展示检查：

| 场景 | 预期行为 |
|------|----------|
| 抽取 API 失败或解析失败 | failed；示例进程保持可继续操作；反馈保存失败，不能显示“已记住” |
| 数据库提交异常 | 不显示全部保存成功；保留已核验提交；结果未知时提示未确认，不承诺整次自动回滚 |
| MySQL 已提交但向量写入失败 | 已保存事实仍存在；同步显示失败或部分完成，不显示“已可检索” |
| 同步处理的是其他记录 | 返回统计，但当前记忆必须单独核验，不借总 done 宣称成功 |
| 检索故障 | 显示检索失败，与“没有相关记忆”区分；不能用通用模型答案冒充历史回忆 |

首次验收同时检查宿主日志与暴露给用户的错误信息，不含 API Key、数据库密码、完整连接字符串或笔记全文。

## 6. 验收脚本输出约定

verify_phase13.py 只连接配置中的本地演示环境，读写独立验收身份；不自动清空表或 collection。all 模式通过两个独立子进程执行 write 与 recall，manifest 只用于传递身份、运行标记、turn_id 和已核验的 ID 等测试元数据，不缓存对话答案。

报告至少包含：运行时间、执行命令、各用例编号与 pass/fail/skip、脱敏 scope、turn_id、memory_ids、写入与同步统计、实际耗时、失败原因。验收报告仅保存必要元数据，不保存原始笔记全文、模型完整 prompt 或凭据。

退出码约定：0 表示所有 P0 通过；1 表示至少一个验收断言失败；2 表示环境缺失或关键检查无法执行。子进程非零退出必须传播到 all 模式。关键用例 skip 不能得到退出码 0。
