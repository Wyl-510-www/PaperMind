# Requirements — Phase 2.2: PDF 文本提取

**日期**：2026-10-08  
**状态**：待实施  
**分支**：`feature/phase-2.2-pdf-extraction`

## 1. 目标与前置条件

本阶段实现 PDF 文本提取能力，允许用户上传单份 PDF 论文并提取其文本内容，复用现有的笔记保存和检索流程。该功能作为 P2 增强项，在 Phase 2 核心闭环通过后实施。

**前置条件**：
- Phase 2（Streamlit 单页 UI）已完成并通过 P0 验收
- 现有的笔记输入、保存、同步和检索流程可正常工作
- 本地 MySQL、Qdrant 和模型服务可用

## 2. 范围决策

### 2.1 本阶段必须交付（P0）

1. **PDF 上传**：Streamlit 页面支持单份 PDF 文件上传（<10MB）
2. **文本提取**：从 PDF 中提取纯文本内容，保留基本段落结构
3. **内容预览**：提取后展示前 500 字符预览，供用户确认可读性
4. **标题提取**：尝试从 PDF 元数据或首页提取论文标题
5. **流程复用**：提取的文本进入现有的"阅读结论"输入框，用户可编辑后保存
6. **错误处理**：明确提示不支持的 PDF 类型（图片扫描版、加密）
7. **文件清理**：临时上传文件在处理后自动删除

### 2.2 明确不在本阶段

- **文档分块与向量化**：不实现文档级 RAG，PDF 全文不作为独立向量存储
- **OCR 识别**：仅支持可复制文本的 PDF，扫描版需明确提示不支持
- **批量上传**：一次只处理一份 PDF
- **文件管理**：不保存原始 PDF 文件，不提供论文库功能
- **高级提取**：不提取图表、公式、参考文献等结构化内容
- **元数据抽取**：不解析作者、会议、年份等字段（可作为后续增强）

## 3. 用户流程与验收语义

### 3.1 PDF 上传与提取

```
用户在 Streamlit 页面：
1. 点击"上传 PDF 论文"按钮
2. 选择本地 PDF 文件（<10MB）
3. 系统自动提取文本并展示预览
4. 提取的标题自动填入"论文标题"字段（可编辑）
5. 提取的全文或用户编辑后的摘要填入"阅读结论"（可编辑）
6. 后续保存流程与现有手动输入完全一致
```

### 3.2 提取质量反馈

| PDF 类型 | 系统行为 |
|---------|---------|
| 可复制文本的论文 | 成功提取，展示预览 |
| 图片扫描版 | 提示"检测到扫描版 PDF，暂不支持 OCR" |
| 加密 PDF | 提示"PDF 已加密，无法提取文本" |
| 损坏文件 | 提示"PDF 文件损坏或格式不支持" |
| 提取结果为空 | 提示"未能提取到文本内容" |

### 3.3 内容处理规则

- **长文本截断**：提取全文，但仅展示前 500 字符预览
- **用户可编辑**：用户可以只保存摘要或关键结论，不强制保存全文
- **保存语义**：保存的内容仍是"用户阅读结论"，不声称系统已读取全文
- **检索行为**：保存后的内容按现有流程写入 Memory V2，可被检索

## 4. 技术选型决策

### 4.1 PDF 解析库

**选择**：PyMuPDF (fitz)

**理由**：
- 纯 Python 实现，无需系统依赖
- 性能优秀，适合单文件快速提取
- 支持元数据读取（标题、作者等）
- 成熟稳定，广泛应用于学术场景
- MIT 协议，无商业使用限制

**备选**：pdfplumber（如 PyMuPDF 遇到兼容性问题）

### 4.2 文件存储策略

**选择**：临时文件处理

**理由**：
- 上传文件保存到 `papermind-host/tmp/uploads/` 临时目录
- 提取完成后立即删除
- 不保存原始 PDF，减少存储需求
- 符合 roadmap 明确延期的"PDF 批量上传和文件管理"

## 5. 集成点与影响范围

### 5.1 修改现有模块

| 模块 | 修改内容 | 影响评估 |
|-----|---------|---------|
| `streamlit_app.py` | 增加 PDF 上传组件 | 低风险，独立功能区 |
| `pyproject.toml` | 添加 PyMuPDF 依赖 | 无影响 |
| `.gitignore` | 忽略 `tmp/uploads/` | 无影响 |

### 5.2 不修改的模块

- `memory_writer.py` - 保存逻辑完全复用
- `memory_retrieval.py` - 检索逻辑完全复用
- Memory V2 核心 - 无任何修改

### 5.3 降级方案

如 PDF 提取遇到阻塞问题：
1. 保留手动输入入口不变
2. PDF 功能标记为"实验性"或移除
3. 不影响现有核心流程

## 6. 非功能性需求

### 6.1 性能
- 单份 PDF（<10MB）提取时间 <5 秒
- 不阻塞 Streamlit 主线程（使用异步处理）

### 6.2 安全
- 文件大小限制：10MB
- 仅接受 `.pdf` 扩展名
- 上传文件保存在受控目录
- 处理后自动清理临时文件

### 6.3 用户体验
- 提取过程显示进度提示
- 提取失败时明确说明原因
- 提取的文本可预览和编辑
- 不强制用户保存全文

## 7. 验收标准

参见 `validation.md`

## 8. 已知限制

1. **仅支持文本 PDF**：扫描版 PDF 需要 OCR，不在本阶段
2. **无结构化解析**：不提取章节、图表、公式
3. **无文档 RAG**：全文不作为独立向量存储
4. **单文件处理**：不支持批量上传
5. **临时存储**：不保留原始 PDF 文件

## 9. 后续增强方向（Phase 3+）

- 支持 OCR 识别扫描版 PDF（pytesseract）
- 提取参考文献和引用关系
- 文档分块与全文 RAG
- 论文库管理（保存、去重、元数据）
- 批量上传和处理队列
