# Roadmap — PaperMind 三天交付版

**调整日期**：2026-10-07

**交付目标**：以已完成的 Phase 1.1（智能体宿主）和 Phase 1.2（记忆检索）为基础，在接下来的三天内完成剩余工作，交付一个本地运行、可在五分钟内演示的论文笔记与长期记忆助手。

**排期假设**：一名开发者，每天约 6–8 小时，复用现有 Memory V2、MySQL、Qdrant 和模型客户端。

## 1. 本次交付边界

只围绕一个使用场景完成闭环：

> 用户粘贴论文摘要或阅读结论 → 系统保存用户确认的笔记 → 关闭并重新启动应用 → 同一用户询问此前记录 → 系统检索长期记忆，展示来源并据此回答。

目标界面采用 **Streamlit 单页应用**，直接调用 Python 业务层。继续复用现有聊天示例作为联调与兜底入口，不同时开发完整 CLI 和另一套前后端。网页开发以第一天真实闭环通过为前提。

三天内以本路线图的范围为准。`mission.md`、`tech-stack.md` 以及[项目说明书](../docs/superpowers/specs/2026-10-07-papermind-design.md)保留长期定位；其中 PDF 上传、完整论文库和文档级 RAG 等要求延期。旧阶段规格中的自动后台 worker、多 Lane 全面接入和严格延迟指标，也不作为本次交付条件。

### 必须完成（P0）

| 能力 | 最小实现 | 验收方式 |
|------|----------|----------|
| 论文笔记输入 | 输入论文标题、粘贴摘要或个人阅读结论 | 能记录一篇论文的阅读笔记 |
| 真实记忆写入 | 调用 Memory V2 写入已确认的用户陈述，优先接通 Fact Lane | MySQL 中存在对应记录；写入失败时不显示“已保存” |
| 查询门控 | 提问只触发检索，不当作新的阅读结论保存 | 纯查询前后，相关事实记录数量不增加 |
| 向量索引同步 | 复用核心 Outbox 消费能力；先提供可重复执行的同步入口 | 完成同步后，Qdrant 能检索到刚保存的记忆 |
| 跨会话回忆 | 清空会话历史并重启应用后，重新检索 MySQL / Qdrant | 相同用户可回忆笔记，无需重新粘贴 |
| 证据展示 | 展示实际检索内容和 Memory ID；有来源时间时一并展示 | 回答可对应到真实证据，不伪造页码或来源 |
| 无证据与失败提示 | 未找到记忆、检索失败、写入失败分别提示 | 不把服务故障当作“没有历史记录”，不编造用户经历 |
| 用户范围隔离 | 每次写入与检索传递 tenant_id、user_id；使用三个固定组合：(tenant_A, user_A)、(tenant_A, user_B)、(tenant_B, user_A) | 同租户不同用户、不同租户相同用户均不串记忆 |
| 可运行入口 | 至少通过现有聊天示例完成核心流程 | 实际可输入、保存、提问和查看证据 |
| 交付材料 | 本地启动说明、验收脚本、五分钟演示脚本及录屏 | 按说明启动并重复演示 |

**输入规则**：三天版以粘贴文本为主，不要求解析 PDF。保存笔记时用户确认保存；对话提问不自动保存为事实。只保存用户输入，不把模型生成的答案写成用户事实。

**回答规则**：历史回忆只能基于检索到的记忆。对于用户当前提供的摘要，可以分析该摘要，但必须区分“当前输入”与“历史记忆”。首版不宣称已读取论文全文或具备页码级引用能力。

### 展示目标（P1，Day 1 闭环通过后执行）

- 一个 Streamlit 页面：身份选择、笔记输入、提问、答案和证据。
- 直接复用同一业务入口，不另外开发 REST API 或第二套对话逻辑。
- 网页未完成时，允许交付经验证的聊天示例，必须明确标记网页未交付。

### 有余量再做（P2）

仅在 P0 和网页全部通过、且第三天验收与录屏时间已保留时选择一项，不累加排期：

- 基于当前粘贴摘要生成“研究问题 / 方法 / 结果 / 局限”四项概览；原文未说明的内容明确标注，保存前由用户确认。
- 支持一份可复制文本的 PDF 提取，复用同一文本输入流程；不增加分块向量库、OCR 或论文库管理。

### 明确延期

- React、FastAPI、WebSocket、流式输出以及独立前后端部署。
- 完整 CLI 命令集、Rich 输出美化和单独的记忆管理界面。
- PDF 批量上传、文件去重、元数据自动抽取、文档分块与全文 RAG。
- 论文库搜索、阅读状态管理、笔记版本编辑、记忆删除与回滚。
- 独立实验记录、任务规划、提醒系统和知识图谱。
- 多模型切换、Redis、正式账号登录、云部署、监控和性能专项优化。

## 4. 最终验收清单

验收必须使用真实本地 MySQL、Qdrant 与模型服务。离线 Mock 测试用于回归，不作为持久化、检索或隔离已打通的证据。

- [ ] **记录笔记**：保存“论文：Attention Is All You Need；我的阅读结论：核心方法是自注意力机制”，MySQL 存在对应用户事实。
- [ ] **同步可检索**：执行 Outbox 同步入口后，检索返回对应内容与 Memory ID；记录实际等待时间，不预先承诺两秒内完成。
- [ ] **跨会话持久化**：关闭应用并重新启动，清空旧会话历史，同一用户仍能回忆该笔记。
- [ ] **查询不误写**：询问“我之前记录过哪些 Transformer 论文结论？”，不新增该问题对应的事实记忆；不要求 Outbox 或日志行数不变。
- [ ] **证据对应**：答案中的历史结论能对应到显示的检索证据；不能仅凭模型常识声称用户读过某篇论文。
- [ ] **无证据行为**：询问未记录的论文，明确表示未找到相关历史记忆，不虚构用户阅读经历。
- [ ] **用户隔离**：同一租户换另一个用户，无法查到上述笔记。
- [ ] **租户隔离**：保持相同用户 ID，切换租户后无法查到上述笔记。
- [ ] **失败反馈**：分别模拟写入失败与检索失败，显示对应错误，不能显示“保存成功”或假装已查过历史记忆。
- [ ] **重复演示**：完整流程至少连续通过两次；测试使用独立演示身份或可识别的笔记，避免旧数据掩盖失败。
- [ ] **交付材料**：提供启动说明、验收脚本及结果、五分钟演示脚本和录屏。

验收脚本应报告通过 / 失败 / 跳过；关键服务不可用时明确失败或阻塞。P0 项不能通过跳过测试来宣布完成。
