# PaperMind 科研论文阅读管理助手项目说明书

## 1. 项目概述

### 1.1 项目名称

PaperMind：基于长期记忆的科研论文阅读管理助手。

### 1.2 项目目的

本项目用于完成 AI 应用课程作业，面向本科生和研究生，解决论文阅读过程中“资料分散、重点难找、笔记难以持续积累、读过的论文容易遗忘”的问题。

首版应用采用网页形式，用户上传 PDF 后，系统自动生成结构化摘要，支持用户补充阅读笔记、修改阅读状态，并在后续对话中检索论文内容和历史阅读记录。

### 1.3 项目价值

普通 PDF 阅读器只能保存文件和手写笔记，普通聊天机器人又无法长期记住用户的研究方向和阅读记录。PaperMind 将论文资料管理、AI 内容提炼、个人笔记和长期记忆结合，使用户能够持续积累可检索的科研知识。

## 2. 用户与使用场景

### 2.1 首版用户

- 本科生；
- 研究生；
- 需要整理课程论文、毕业论文或研究资料的学生。

首版不针对高校教师团队协作、科研机构知识库或商业文献数据库设计。

### 2.2 典型用户故事

1. 用户上传一篇论文 PDF。
2. 系统提取论文文本并生成结构化摘要。
3. 用户查看研究问题、方法、数据、结果、局限和关键词。
4. 用户补充个人理解、疑问和评价。
5. 用户将论文状态设置为“阅读中”或“已读”。
6. 数天后，用户搜索相关论文或询问自己以前记录的观点。
7. 系统结合论文内容、个人笔记和 Memory V2 中的用户研究记忆回答。

## 3. 首版范围

### 3.1 必须实现

- 用户标识级的数据隔离；
- PDF 上传、文件哈希去重和文本提取；
- 论文元数据保存；
- 六字段 AI 结构化摘要；
- 个人阅读笔记的新增、修改和保存；
- 四阶段阅读状态；
- 论文列表、关键词搜索和状态筛选；
- 论文正文分块向量化和语义检索；
- 基于论文内容、个人笔记和用户长期记忆的论文问答；
- 将用户研究方向、阅读结论和后续问题写入 Memory V2；
- Streamlit 网页演示界面；
- 离线单元测试和最小集成测试。

### 3.2 首版不实现

- 全网论文搜索和自动下载；
- 扫描版 PDF 的 OCR；
- 正式学术论文或完整文献综述的自动代写；
- 复杂引用格式排版和参考文献自动校对；
- 多人协作、评论和团队权限；
- 完整账号注册、密码找回和第三方登录；
- 移动端原生应用；
- 自动判断研究结论是否科学正确。

## 4. 功能需求

### FR-01 用户范围

系统的每次业务调用必须携带 `user_id`。论文、摘要、笔记、状态、向量检索结果和 Memory V2 记忆均按 `user_id` 隔离。

首版可以通过 Streamlit 的会话输入或固定演示用户进入系统，但业务层不能省略 `user_id` 参数。正式登录功能在后续版本实现。

### FR-02 PDF 上传

系统应支持用户上传单个 PDF 文件，并完成以下校验：

- 文件扩展名为 `.pdf`；
- 文件内容不为空；
- 文件大小不超过 30 MB；
- 使用 SHA-256 计算文件哈希；
- 同一用户上传相同哈希时返回已有论文记录，不重复解析。

上传成功后，系统创建 `Paper` 记录并进入文本提取流程。

### FR-03 文本提取

首版使用 `PyMuPDF` 或等价的本地 PDF 解析库提取文本。系统应保存页码信息，保证后续检索结果能够回溯到页码。

对于无法提取有效文本的 PDF，系统保留上传记录并显示“文本提取失败，请上传可复制文本的 PDF”。OCR 不属于首版范围。

### FR-04 论文元数据

系统应保存以下字段：

- 论文标题；
- 作者；
- 发表年份；
- 来源或期刊；
- 摘要原文（如果 PDF 能识别）；
- 用户标签；
- 文件哈希；
- 文件路径；
- 阅读状态；
- 创建时间和更新时间。

如果模型无法从论文中确定某个元数据，字段保存为空，不得让模型编造。

### FR-05 结构化摘要

用户上传论文后，系统调用大语言模型生成严格结构化结果，字段固定为：

1. `research_question`：研究问题；
2. `method`：研究方法；
3. `data`：数据集、实验对象或样本；
4. `results`：主要结果；
5. `limitations`：局限性；
6. `keywords`：关键词数组。

模型输出必须经过 Pydantic 校验。字段缺失或格式错误时，系统保留原文并允许用户重新生成摘要，不得把未经校验的模型文本写入结构化字段。

### FR-06 阅读笔记

用户可以在论文详情页新增和修改个人笔记。笔记至少包含：

- `paper_id`；
- `user_id`；
- 笔记正文；
- 创建时间；
- 更新时间。

笔记保存成功后，用户刷新页面仍能看到原内容。用户笔记属于私有数据，不参与其他用户的检索。

### FR-07 阅读状态

论文状态固定为以下四种：

- `unread`：未读；
- `reading`：阅读中；
- `read`：已读；
- `review`：需复习。

论文列表页支持按状态筛选，论文详情页支持切换状态。

### FR-08 论文分块与检索

系统将论文文本按段落和页码分块，每个分块保存：

- `paper_id`；
- `user_id`；
- 页码；
- 分块序号；
- 原文；
- 向量索引 ID。

用户搜索或提问时，系统优先检索当前用户的论文分块，再根据相似度和页码组织上下文。检索结果必须带论文 ID 和页码。

### FR-09 论文问答

用户可以在论文详情页输入问题。回答上下文由以下三部分组成：

- 当前论文的相关正文分块；
- 当前论文的结构化摘要和个人笔记；
- Memory V2 返回的用户研究方向、历史结论和待办问题。

系统提示词必须要求模型只依据提供的上下文回答；上下文没有答案时，回答“当前资料中没有足够依据”。

### FR-10 Memory V2 记忆

论文阅读过程中，以下内容可以写入 Memory V2：

- 用户长期研究方向；
- 用户关注的关键词；
- 用户对论文的明确评价；
- 用户确认的重要研究结论；
- 用户提出的后续研究问题；
- 用户计划继续阅读或验证的任务。

论文原文和论文结构化数据不直接当作用户长期记忆保存。原文使用 PaperMind 自己的论文数据表和向量集合管理。

## 5. 技术架构

~~~text
┌────────────────────────────────────────────┐
│ Streamlit 网页界面                         │
│ 论文库 / 上传 / 详情 / 笔记 / 问答          │
└─────────────────────┬──────────────────────┘
                      ▼
┌────────────────────────────────────────────┐
│ PaperMind 应用服务层                       │
│ PDF 解析、摘要、笔记、状态、检索、问答编排  │
└───────────┬────────────────┬───────────────┘
            │                │
            ▼                ▼
┌──────────────────┐  ┌──────────────────────┐
│ PaperMind 数据层 │  │ Memory V2 适配层     │
│ 论文/摘要/笔记   │  │ 用户长期记忆读写     │
└────────┬─────────┘  └──────────┬───────────┘
         │                       │
         ▼                       ▼
   MySQL + Qdrant          MySQL + Qdrant
   论文数据与分块索引      用户事实与记忆索引
~~~

### 5.1 技术栈

- Python 3.11+；
- Streamlit；
- PyMuPDF（PDF 文本提取）；
- Pydantic（结构化模型和模型输出校验）；
- SQLAlchemy 2.x；
- MySQL 8.0+；
- Qdrant；
- DashScope / OpenAI 兼容接口；
- DashScope `text-embedding-v4`；
- `memoryV2-core` 的 `server.memory_v2` 包；
- pytest 和 pytest-asyncio。

### 5.2 数据库边界

PaperMind 可以与 Memory V2 共用 MySQL 实例，但必须使用独立的应用表名前缀，例如 `papermind_papers`、`papermind_summaries`、`papermind_notes` 和 `papermind_chunks`。Memory V2 的事实表、事件表和 Outbox 表由核心模块管理。

论文分块使用独立的 Qdrant collection，例如 `papermind_paper_chunks`；用户长期记忆继续使用 Memory V2 当前配置的 collection。两个 collection 的用途和权限过滤不能混用。

应用服务层必须提供以下接口，Streamlit 页面只能调用服务接口，不能直接操作数据库：

~~~python
def ingest_pdf(file_bytes: bytes, filename: str, user_id: str) -> Paper:
    """校验 PDF、去重、提取文本并创建论文记录。"""

def generate_summary(paper_id: str, user_id: str) -> PaperSummary:
    """读取论文文本，调用模型并校验六字段摘要。"""

def update_note(paper_id: str, user_id: str, content: str) -> ReadingNote:
    """保存或更新当前用户的论文笔记。"""

def update_status(paper_id: str, user_id: str, status: str) -> Paper:
    """更新阅读状态，只接受四种枚举值。"""

def search_papers(user_id: str, query: str, status: str | None = None) -> list[Paper]:
    """在当前用户范围内搜索论文。"""

async def ask_paper(paper_id: str, user_id: str, question: str) -> Answer:
    """检索论文、笔记和 Memory V2 后生成有依据的回答。"""
~~~

### 6.1 Memory V2 适配要求

优先使用 `memoryV2-core` 已有的生产入口，不修改核心模块内部实现：

- 读取：`server.memory_v2.production_entry.assemble_evidence_pack(query, tenant_id, user_id)`；
- 兼容读取：`server.memory_v2.production_entry.assemble_user_memory(...)`；
- 写入：`server.memory_v2.wiring.create_memory_writer(llm_client, tenant_id)` 后调用 `write_turn(...)`；
- 已有 mem0 兼容对象时，可使用 `server.memory_v2.wiring.create_facade(...)`。

每次读写必须传递稳定的 `tenant_id`、`user_id` 和 `turn_id`。Memory V2 写入失败时记录日志并返回降级结果，不得阻断论文上传、笔记保存和状态修改。

### 7.2 上传页面

### 7.3 论文详情页

## 8. 模型提示词约束

摘要提示词必须包含以下规则：

1. 只能依据输入论文文本；
2. 不确定的内容填写“原文未说明”；
3. 输出六个固定字段；
4. `keywords` 必须是字符串数组；
5. 不得虚构作者、数据规模、实验结果或发表信息。

问答提示词必须包含以下规则：

1. 优先引用当前论文正文和个人笔记；
2. 用户长期记忆只能用于补充用户背景，不能替代论文证据；
3. 无足够依据时明确说明；
4. 返回引用的论文页码或“来自个人笔记”的来源类型。

## 9. 错误处理与安全要求

- 所有用户输入必须经过 `user_id` 范围校验；
- 数据库查询必须带用户过滤条件；
- 向量检索必须使用 `user_id` payload filter；
- 文件名不得直接作为存储路径，使用安全文件名和 UUID；
- 不在日志中打印论文全文、用户笔记或 API 密钥；
- LLM 超时、限流和结构化输出错误需要返回可理解的提示；
- 重试只适用于幂等的摘要生成和向量写入；
- 删除论文时同时删除元数据、笔记、分块向量和关联的应用索引；
- 删除用户记忆必须通过 Memory V2 已有接口或明确的管理服务完成。

## 10. 测试和验收

### 10.1 单元测试

- 空文件、非 PDF 文件和超过 30 MB 文件被拒绝；
- 相同文件哈希在同一用户下不会重复创建论文；
- PDF 分块保留页码和顺序；
- 六字段摘要模型拒绝缺失字段和错误类型；
- 四种阅读状态以外的值被拒绝；
- 笔记更新后读取到最新版本；
- Memory V2 失败时论文基础功能仍返回成功结果。

### 10.2 隔离测试

- 用户 A 搜索不到用户 B 的论文；
- 用户 A 无法读取用户 B 的笔记；
- 用户 A 的向量检索不会返回用户 B 的分块；
- 用户 A 的 Memory V2 证据不会注入用户 B 的问答。

### 10.3 最小演示验收

使用两份公开论文 PDF，完成以下连续操作：

1. 上传第一篇论文并生成六字段摘要；
2. 添加个人笔记并将状态改为“阅读中”；
3. 上传第二篇论文并生成摘要；
4. 在论文库按关键词和状态筛选；
5. 针对第一篇论文提问并显示页码证据；
6. 刷新页面后仍能看到摘要、笔记和状态；
7. 使用同一用户再次提问，系统能检索到先前保存的科研记忆。

## 11. 本地运行与配置

### 11.2 应用配置

~~~dotenv
PAPERMIND_TENANT_ID=papermind-demo
PAPERMIND_UPLOAD_DIR=./data/uploads
~~~
